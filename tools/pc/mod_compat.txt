# The Cheats menu's functions now say whether they did anything (0 before a
# game is loaded); a caller built against v0.1.2's void ignores eax.
accept v0.1.2 function Cheats_GiveAllCards returns int where it returned void
accept v0.1.2 function Cheats_UnlockAllFreeDuelists returns int where it returned void
# The port SDK stand-ins compile against the game's Psy-Q headers: libgte.h
# now declares RotAverageNclip3_nom with the return the resident routine and
# its stand-in always had (the GTE flag word, in v0/eax). A caller built
# against v0.1.2's void ignores eax, which every call may change anyway.
accept v0.1.2 function RotAverageNclip3_nom returns long (the flag word) where it returned void
# PR #105 (the burning card keeps its HD pack image): the recorder gained
# `capture` at its end. Only the port's own OpenGL picture installs a
# recorder; none of v0.1.2's mods calls SoftGpu_SetRecorder.
accept v0.1.2 record SoftGpuRecorder grew by one callback at its end
# The Game list (host actions: Exit game, save states, the other shortcuts):
# every controls profile gained its host bindings at its end, which moves
# what follows a profile. No v0.1.2 mod imports a Controls or
# ControlsRuntime name; the controls file is the port's own and has its own
# version (controls.txt 2).
accept v0.1.2 record ControlsProfile grew by the host action bindings at its end
accept v0.1.2 record ControlsDeviceProfile holds the larger ControlsProfile
accept v0.1.2 record ControlsConfig holds the larger ControlsProfile
# PR #231 (the fusion helper asks a mod's equip bonus): the planner's rules
# gained `bonus` at their end. Only the port's own fusion helper builds a
# FusionRules; none of v0.1.2's mods calls a Fusion_ function.
accept v0.1.2 record FusionRules grew by two callbacks at its end (bonus, bonuses)
# Equips with their own DEF bonus ("bonus_defense"): the duel record's unused
# bytes 0x1A-0x1B hold defense_modifier (offsets and size unchanged; the
# disc never used them), and the planner's card gained defense_modifier at
# its end, which FusionLine holds. None of v0.1.2's mods calls a Fusion_
# function, and a mod reading a record's stat_modifier still reads it.
accept v0.1.2 record DuelCardRecord names two of its pad bytes defense_modifier
accept v0.1.2 record FusionCard grew by defense_modifier at its end
accept v0.1.2 record FusionLine holds the larger FusionCard
